# Frosted Harmony website

A cupcake showcase website for **frostedharmony.com**:

- Gallery that automatically pulls the latest Instagram posts, with `site/gallery.json` as a fallback
- Flavors and "how ordering works" sections
- Inquiry form (pricing, custom orders, events, questions) that emails you, with spam protection, and
  an inbox in the admin portal where every inquiry is kept
- Light and dark mode: follows the visitor's device, with a sun/moon switch
- Admin portal at `/admin/` for changing the page, photos, design, email, Instagram and other
  settings from a browser, with owner/editor roles, optional two-step sign-in, backup/restore,
  hashed passwords, encrypted secrets and an activity log
- Runs on a home Linux server with Docker, published securely through a Cloudflare Tunnel (no router ports opened)

**Start here: [docs/SETUP-GUIDE.md](docs/SETUP-GUIDE.md)**. It has step-by-step instructions from installing Linux to going live.

- [docs/RAID-SETUP.md](docs/RAID-SETUP.md): Areca ARC-1223-8i, 6 x 2 TB in RAID 6, mounted at `/srv/data`, with email alerts
- [docs/EMAIL-SETUP.md](docs/EMAIL-SETUP.md): `cupcakes@frostedharmony.com` through Cloudflare Email Routing and Gmail "Send mail as"
- [docs/ADMIN-SETUP.md](docs/ADMIN-SETUP.md): turning on the admin portal, Cloudflare Access, and recovering a lost password

## Quick reference

Preview on your PC:

```powershell
cd api
npm install
npm run dev     # open http://localhost:8080 (admin portal: http://localhost:8080/admin/)
npm test        # automated tests
```

Publish changes to the server:

```powershell
.\deploy.ps1 -Server dridge@<server-ip> -RemoteDir /srv/data/sites/frostedharmony
```

On the server (first time: `cp .env.example .env` and fill it in):

```bash
cd /srv/data/sites/frostedharmony
docker compose up -d --build
docker compose ps
docker compose logs -f
docker compose exec api node scripts/create-admin.js   # add an owner (--editor for an editor; --list, --reset NAME, --disable-2fa NAME, --role NAME owner|editor)
```

## Layout

| Path | Purpose |
|---|---|
| `site/` | Website files (HTML, CSS, JavaScript, images, `gallery.json`) |
| `site/admin/` | Admin portal pages |
| `site/fonts/` | Self-hosted fonts offered in the Design editor (SIL Open Font License, see `site/fonts/licenses/`) |
| `api/` | Node.js service: Instagram feed cache, inquiry email and the admin portal API |
| `api/lib/` | Settings, sign-in/sessions with roles and two-step sign-in (`totp.js`), encryption, storage, audit log, page content, page renderer, photo library, design (theme and the shared `palette.js` color rules), inquiry inbox, Instagram and backup modules |
| `api/routes/admin.js` | `/api/admin/*` endpoints |
| `api/scripts/create-admin.js` | Creates admin users and recovers access (password reset, two-step sign-in off, role) over SSH |
| `api/test/` | Automated tests (`npm test`) |
| `nginx/` | Web server configuration and shared security headers |
| `docker-compose.yml` | Runs `web` (nginx), `api` and `tunnel` (cloudflared) |
| `.env.example` | Template for server secrets. The real `.env` lives only on the server |
| `deploy.ps1` | Copies the project to the server and restarts the containers |
| `server-tools/` | `raid-check.sh` hourly RAID health email alerts, plus its config template |

## Home page: hand-written vs published

`site/index.html` is the original hand-written page. Once someone presses **Publish** in the admin
portal, the home page is generated by `api/lib/render.js` from the portal's content and served from
the data volume instead, so text edits to `site/index.html` stop showing. To change the page
**layout or markup**, edit `api/lib/render.js` (and keep `site/index.html` in step: the test
`the default content renders exactly the original hand-written page` checks that they match).
The API regenerates the published page on every start, so layout changes reach the live site
after a deploy.

Colors, fonts and shapes are CSS variables defined in `site/styles.css`. The Design editor writes a
small stylesheet that overrides them (`api/lib/theme.js`, served from `/site-assets/`). Its defaults
(`DEFAULT_THEME`) must stay identical to the values in `styles.css`; with the default design no extra
stylesheet is added at all.

Dark mode works the same way: `site/styles.css` has the dark variables for the default design
between the `dark-mode:start` and `dark-mode:end` comments, generated by `darkCss()` in
`api/lib/theme.js` (a test checks they match; regenerate that block if you change the default
colors or the dark-palette rules in `api/lib/palette.js`). `site/theme-mode.js` runs in `<head>`
on both the website and the portal: it sets `data-color-mode` on `<html>` from the visitor's saved
choice or device setting, and handles the sun/moon button.
